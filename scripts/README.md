# 游戏脚本编写

游戏脚本指"驱动游戏逻辑的代码"——角色控制、战斗规则、任务流程、AI 行为等。
这里总结通用的编写模式和设计规范。

## 一、脚本架构的三种常见方式

1. **面向对象（OOP）**
   每个敌人/道具/技能是一个类，继承共同的基类。直观，适合中小项目。
2. **组件/ ECS**
   实体只是 ID，功能由组件组合（位置、血量、渲染、AI）。灵活，适合复杂系统。
3. **数据驱动**
   逻辑写死在代码里，数值/配置放 JSON/CSV/Excel。改平衡性不用改代码。

## 二、必备设计模式

| 模式 | 用途 |
|------|------|
| 状态机 FSM | 角色状态（待机/跑/攻击/死亡）、场景切换 |
| 观察者/事件总线 | 解耦："怪物死亡"事件触发掉血、计分、音效 |
| 对象池 | 子弹/粒子频繁创建销毁，预分配复用避免卡顿 |
| 单例/服务定位器 | 全局资源管理器、音频管理器 |
| 命令模式 | 输入映射、可撤销操作、回放 |

## 三、脚本编写规范

- **逻辑与帧率解耦**：用 delta time，别假设每帧固定 16ms
- **配置外置**：伤害公式可以写死，但具体数值放配置文件
- **避免深层继承**：优先组合，继承层级别超过 3 层
- **热重载**：开发时支持改脚本不重启，效率翻倍
- **日志与调试开关**：关键状态打日志，发布时关掉

## 四、一个角色脚本的例子（伪代码）

```python
class Player:
    def __init__(self):
        self.hp = 100
        self.state = IdleState()      # 当前状态
        self.inventory = Inventory()  # 组件组合

    def update(self, dt, input):
        self.state = self.state.handle(self, dt, input)  # 状态机驱动
        self.inventory.update(dt)

    def take_damage(self, amount):
        self.hp -= amount
        EventBus.emit("player_hurt", amount)  # 事件解耦
        if self.hp <= 0:
            self.state = DeadState()
```

## 五、推荐学习路径

1. 先看 `../examples/` 里的可运行示例，理解循环/状态机/碰撞
2. 用 pygame 或 Godot 做一个 Pong / 贪吃蛇
3. 加上状态机、对象池、配置外置，重构成"框架"
4. 再上事件总线和 ECS，做稍复杂的游戏

示例代码均使用纯 Python 标准库，无需安装依赖即可运行。
