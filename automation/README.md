# 本地客户端自动化（Automation）

只用自己电脑上的画面、鼠标、键盘完成操作，等价于"人手在自己机器上点"。

## 一、明确不做的

- 不抓包、不改包、不伪造协议（不碰通信层）
- 不探测或利用服务端漏洞、不刷接口、不发高频请求
- 不读改游戏内存、不反编译客户端
- 不多开同步、不批量注册、不做任何可能造成服务器负载的行为

这条线不破：所有识别和操作都在本地屏幕上完成，服务器收到的只是普通客户端操作。

## 二、四个模块

```
automation/
├── capture      抓屏（见 vision/vision_kit.py 的 grab）
├── locate       定位（模板匹配 / OCR / 取色）
├── fsm          状态机（巡逻 / 遇战 / 战斗 / 回城 / 卖货）
└── guard        安全阀（异常即停、超时退出、日志、现场截图）
```

## 三、状态机骨架

```
           ┌──────────┐
      ┌───▶│  巡逻 Patrol  │──遇敌──┐
      │    └──────────┘        │
      │         │ 背包满         ▼
      │         ▼          ┌──────────┐
      │    ┌──────────┐    │ 战斗 Battle │
      │    │  回城 Return │    └────┬─────┘
      │    └────┬─────┘    胜利/逃跑 │
      │         ▼                 │
      │    ┌──────────┐           │
      └────│ 卖货 Sell │◀──────────┘
           └──────────┘  背包满才回城
```

每个状态只做一件事：**读当前画面 → 判断 → 发一个动作**。动作发出后立即回到状态机顶部重新读画面，不做"点完就假设成功"的连招。

## 四、安全阀（必须一开始就写）

1. **连续识别失败 N 次（默认 5）→ 立即停止**，保存现场截图，打印当前状态
2. **单次动作后必须复查**：点击后重新截图确认状态是否变化，没变化就记一次失败
3. **总运行时长上限**：到点自动停，避免无人看守跑一整夜
4. **热键中断**：任意键（或指定组合键）立刻暂停
5. **日志**：每个状态切换、每次动作、每次匹配分数都落盘；分数集中在 0.8 附近说明阈值需要调
6. **异常截图存档**：失败时的画面存到 `logs/`，否则事后无从排查

## 五、开发顺序（建议）

1. `capture` 只抓游戏窗口，确认 10 分钟稳定不掉帧
2. 用 `save_template` 把 NPC、按钮、血条、背包格一个个截成模板
3. 写 `巡逻` 单状态，能沿路径点走一圈并正确停下
4. 加 `战斗` 状态，先把"遇敌 → 打 → 恢复巡逻"跑通
5. 最后加 `回城` / `卖货`，加上安全阀
