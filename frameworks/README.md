# 游戏框架 / 引擎选型

按你的目标平台和语言挑一个，别自己从零造轮子。

## 一、成熟引擎（推荐新手）

| 引擎 | 语言 | 平台 | 适合 |
|------|------|------|------|
| **Godot** | GDScript / C# | PC/移动/Web | 开源免费、2D强、上手快，独立游戏首选 |
| **Unity** | C# | 全平台 | 生态最大、资源多，3D/商业项目主流 |
| **Unreal** | C++ / 蓝图 | PC/主机/移动 | 画面顶级、3A 大作 |
| **Cocos Creator** | TypeScript | 移动/Web | 国内手游、小游戏常用 |
| **Love2D** | Lua | PC | 轻量 2D，纯代码党 |

## 二、代码库框架（自己掌控底层）

| 框架 | 语言 | 适合 |
|------|------|------|
| **pygame** | Python | 2D 入门、教学、小游戏 |
| **Phaser** | JavaScript | HTML5 网页游戏 |
| **libGDX** | Java | 跨平台 2D/3D |
| **SFML** | C++ | 轻量跨平台多媒体 |
| **Raylib** | C | 极简、适合学图形原理 |
| **Bevy** | Rust | ECS 架构、性能好 |

## 三、框架搭建的核心模块

不管用哪个引擎，一个游戏框架通常都要搭这几层：

```
┌─────────────────────────────┐
│      场景管理 Scene          │  菜单 / 关卡 / 战斗切换
├─────────────────────────────┤
│      游戏循环 Loop           │  固定步长 update + render
├─────────────────────────────┤
│  实体系统 Entity/ECS         │  对象组织、组件组合
├─────────────────────────────┤
│  资源系统 Asset              │  图片/音效/配置加载与缓存
├─────────────────────────────┤
│  输入 Input / 物理 Physics    │  键鼠手柄、碰撞与运动
├─────────────────────────────┤
│  UI / 音频 / 网络            │  按项目需要接入
└─────────────────────────────┘
```

## 四、选型建议

- **第一次做游戏** → Godot 或 pygame，先把"能跑起来"做出来
- **做手游/小游戏** → Cocos Creator
- **找工作/ commercial** → Unity
- **想深入底层原理** → Raylib / 自己用 SDL2 搭

详细的脚本编写模式见 `../scripts/README.md`。
